# AGENTS.md — hyprview

Плагин Hyprland, C++23. Правила и требования. Обоснования — в `docs/REFERENCE.md`,
история — в git. Файл декларативный: утверждение или требование, без объяснений.

Справочные данные: `docs/REFERENCE.md` — карта исходников, блюр-пайплайн, формат
трейса, реестр анимаций, приоритет настроек.

---

## 0. Правило №0

**Сначала лог, потом правка.**

| Ситуация | Действие |
|---|---|
| «выглядит неправильно» | включить `debug_trace`, воспроизвести, прочитать `LIFE\|` `DRAG\|` `SCROLL\|` `SWAP\|` `ANIM\|` `RING\|` `GL\|` `CURSOR\|` |
| гипотеза о причине | запись, которая её подтвердит или опровергнет, — **до** правки кода |
| правка «на всякий случай» | запрещена |

Отсутствие записи ≠ отсутствие события. Анимация, применённая но не записанная,
неотличима от неприменённой.

## 1. Безопасность сессии

Краш, use-after-free или RASSERT внутри плагина **роняет всю сессию пользователя**.

| # | Требование |
|---|---|
| 1.1 | Рискованные правки (хуки, порядок проходов, teardown, private GL) — только в nested Hyprland |
| 1.2 | Хуки ставятся по demangled-signature substring: `shouldRenderWindow`, `damageSurface`, `CSeatManager::setPointerFocus/setKeyboardFocus`. После обновления Hyprland: `ctest -R hook_signatures` |
| 1.3 | Hot-reload — только целью `reload`. Ручной `plugin load` рядом с hyprpm-копией даёт два инстанса |
| 1.4 | `-fno-gnu-unique` не удалять из `CMakeLists.txt`. Иначе static-init guard'ы становятся `STB_GNU_UNIQUE`, `dlclose` не выгружает |
| 1.5 | Перед `git checkout` проверять файлы вне git: tracked на одной ветке + gitignored на другой |

## 2. Правила кода

Колонка «нарушение» — наблюдавшееся отступление от правила, с идентификатором.

| # | Правило | Нарушение наблюдалось |
|---|---|---|
| 2.1 | Immediate-mode GL только через `gl_util.hpp`: `safeRenderRect`, `drawable()`, `dropShadow`, `strokeRing`/`strokeRingPx` | `RASSERT(w>0 && h>0)` — `OpenGL.cpp:1071/2163/2341`. Проверяет `scan_draw_sites` |
| 2.2 | Весь chrome в monitor-local логических пикселях; перед GL — через `pxb()`/`pxr()`; `.round()` обязателен | pixman trunc'ает дробные боксы → дырки в тонких рамках |
| 2.3 | Всё, что рисует в приватный FBO: `RPT_EXPORT` + `fbSize=(W,H)` с сохранением и восстановлением окружения | иначе портится последующий рендер |
| 2.4 | Конфиг только через `cfg*`-хелперы (V2 `value()`) | `HyprlandAPI::getConfigValue()` игнорирует Lua-конфиг |
| 2.5 | `const double x = cfg::…` в namespace scope — нельзя | инициализатор до `PLUGIN_INIT`, конфиг ещё не прочитан |
| 2.6 | Заголовки Lua (`<lua.h>`, `<lauxlib.h>`) — внутри `extern "C"` | без него `dlopen` падает с `undefined symbol: _Z14luaL_checktype` **до** `PLUGIN_INIT`. Файлы: `src/anim.cpp`, `src/clock/curves.cpp` |
| 2.7 | Порядок `paint()` не менять без причины (`render/painter.cpp`) | см. §3.4 |
| 2.8 | Файлы, которые ctest компилирует без `hyprland/`, не получают его include никогда | один include превращает тест на 0.4 с в ошибку линковки. Проверяет `scan_hypr_types` |
| 2.9 | Карта по окнам держит **владельца**: значение несёт `PHLWINDOWREF` и роняет запись при `expired()` | проверять тип ключа бессмысленно: все три map'а в `pixel/cache.hpp` ключуются сырым `CWindow*` и все три правы |
| 2.10 | Каждый `m_place.clocks.*.begin()` обязан стоять рядом с `trace::animStart`, либо быть в списке исключений **с причиной** | анимация, применённая но не записанная, неотличима от неприменённой. Проверяет `scan_anim_coverage` |
| 2.11 | `hl.config{…}` в пользовательском конфиге — под `pcall`; `hl.plugin.load` тоже | без `pcall` ошибка одного ключа обрушивает загрузку: Hyprland выходит молча. `plugin.load` глотает ошибку загрузки `.so` — выглядит как «конфиг не подхватился» |
| 2.12 | `currentFB` нельзя использовать как источник блюра/полос | фуллскрин-окно на активном воркспейсе идёт через solitary-client fast path в обход `shouldRenderWindow`. Источники только `backdropSource()` / `renderBackdropSource()` |
| 2.13 | Не деактивировать mid-frame: финальный кадр овервью обязан отрисоваться | иначе один прозрачный кадр поверх десктопа. Механику держит `Lifecycle::requestDeactivate()`, порядок вызовов — в `lifecycle.cpp` |
| 2.14 | Владение вводом ≠ скрытие окон | `shouldRenderWindow` прячет окна только от рендерера; фокус им раздаёт `CSeatManager`, и через `Event::bus()` это не отменяется. Пока овервью владеет экраном (**включая паркованные кадры** — `openedOrParked()`, не `active()`), хуки `setPointerFocus`/`setKeyboardFocus` не дают фокусу уйти в окна. Хук на `send*` бесполезен |
| 2.15 | Геометрия в `render/` принимает сторону/якорь и настройки аргументами и **никогда** не читает `cfg::`. Решение о капсуле и о полёте — тоже аргументами: `captionLayout` (где пилюли), `pushOut` (куда уходят из-под карточки), `swapFlight` (четыре вида полёта) | иначе стрип, который перестаёт быть фиксированной полосой у края (`docs/ROADMAP.md`), становится переписыванием каждой такой функции. Обёртка `Overview::` собирает входы, `render::geometry` считает. Проверяет `scan_render_config`: в **чистых** заголовках `render/` (`geometry.hpp`, `tile_look.hpp`) — `cfg::` быть не должно, ноль и не ратчет. Чтение там уводит заголовок из-под всех header-only тестов |
| 2.16 | Конфиг читается по месту использования, каждый кадр | кэширование значения конфига в поле (`m_softwareOnly`) делает настройку единственной, требующей перезапуска |
| 2.17 | `SubjectRef` — идентичность без владения. `windowOf()` не строит `SP` из `s.id`; владеет источник: `enumerate()` (не `const`) пересобирает список живых, `windowOf()` ищет в нём и отдаёт копию. Устаревшая идентичность → `null`, не указатель | `buildTiles()` строил `SP` из адреса, чьё владение кончалось вместе с циклом: `CSharedPointer<CWindow>::_delete` → `~CSharedPointer` → `buildTiles`. Проверяет `scan_subject_ownership` |
| 2.18 | `src/model/` не называет `PHLWINDOW`. Вкладки окна не имеют: поле, типизированное окном, — это поле, пустое в другом домене | `Ghost`/`WinPulse`/`SwapFX`/`StripWin` держали `PHLWINDOWREF`: у вкладки была бы карточка без пульса, призрака, обмена и перетаскивания. Воркспейсы правилом не покрыты — у вкладки их нет, и `StripItem::ws`/`newWorkspaces()` рабочие по природе. Проверяет `scan_model_window_types` |
| 2.19 | Окно браузера сопоставляется окну Хайпрленда **по pid процесса браузера**, один к одному. Два претендента на pid → не сопоставлено никто | расширение не знает про Хайпрланд, плагин не знает про `browser.windows`; общий знаменатель — процесс, запустивший медиатор. Заголовок не используется: браузер дописывает к нему своё имя (§2.26), а подстановка/префикс — угадывание, и вкладки одного браузера оказываются в окне другого. Коллизии считаются с **обеих** сторон до сопоставления, иначе результат зависит от порядка обхода `unordered_map`. Проверяет `tab_match` |
| 2.20 | Источник вкладок **не содержит ни одного Hyprland-типа**: у вкладки нет ни окна, ни поверхности, ни воркспейса. `SubjectRef{id, generation}` — id это id вкладки, epoch это соединение | `virtual` на `IContentSource` был обещанием второй реализации, которой не существовало. Группа вкладки — **окно браузера**, никогда не воркспейс: композитор о вкладках не знает, и id воркспейса здесь было бы непроверяемым утверждением. Глаголы без транспорта возвращают `false`. Проверяет `tab_source` |
| 2.21 | PNG читается через `cairo_image_surface_create_from_png` + `createTexture(cairo_surface_t*)`. **Не** через `loadAsset` | `resolveAssetPath` подставляет `<assetdir>/hypr/` (`Renderer.cpp:1477`), произвольный путь туда не подставится. cairo уже в `ldd build/hyprview.so` — зависимость не добавляется. `cairo_surface_status` обязателен: cairo на ошибку возвращает **поверхность в ERROR-статусе, а не null**, и без проверки на GPU уходит изображение нулевой ширины. Проверяет `png_read` |
| 2.22 | Кэш картинок субъекта: ключ `SubjectRef{id, epoch}`, **смена epoch очищает кэш целиком**. `null`-текстура не хранится | окно держит владельца рядом с записью, потому что адрес переиспользуется (§2.9). У вкладки нет ни адреса, ни владельца — есть соединение, выдавшее id, и оно играет ту же роль. Мусор от прошлого соединения отдал бы страницу одной вкладки под заголовком другой. Проверяет `subject_cache` |
| 2.23 | Ключ конфига, который никто не читает — **провай**, не предупреждение. Проверяется выражение поля (`colors.label`), а не имя ключа (`label_color`) | `scan_config_keys` доказывает регистрацию, а её набирает одна строка. `tile_mode` пролежал зарегистрированным и непрочитанным всю работу над вкладками: дефолт `"windows"` случайно совпадал с поведением, и юзер с `tile_mode = "tabs"` получал тишину. Проверяет `scan_config_keys_read` |
| 2.24 | Матч «окно браузера → вкладки» строится **в buildTiles()**, из того же перечисления, что и плитки | считался в loadTabs() до buildTiles() — набор окон там был от прошлого прохода, и переключение all-workspaces делало матч мгновенно устаревшим. Две половины одного вопроса из двух разных списков окон — это ровно тот класс расхождения, который запрещает §2.9 |
| 2.25 | Расширение **не пишет файлы** ни на одном движке: `downloads` требует диалога и не перезаписывает, File System Access API нет в Gecko. Поэтому мост обязателен, а не возможен | единственное общее подмножество Gecko и Chromium — WebExtensions. CDP и BiDi оставляют половину браузеров пользователя без отчёта. Шов сделан файловым именно поэтому: плагин не меняется ни на строчку |
| 2.26 | `w->m_title` окна **не равно** `tab.title` расширения: браузер дописывает к заголовку окна имя приложения (`tab.title + " — Zen Browser"`). Поэтому заголовок не годится как ключ сопоставления ни на Firefox, ни (надёжно) на Chromium — ключ это pid (§2.19) | измерено: `m_title` = `(31) Ежи Сармат ... - YouTube — Zen Browser`, тогда как `hyprctl clients` печатает `Strata: ... — Zen Browser`, а расширение отдало бы только `(31) Ежи Сармат ... - YouTube` |
| 2.27 | Временный аддон в релизной сборке **не может** использовать native messaging: порт открывается и сразу закрывается без причины, хост не запускается. Постоянная установка требует подписанного XPI, а подпись в релизной сборке обязательна | проверено A/B: подстановка `/usr/bin/env` вместо своего хоста дала **то же самое** — значит плох не хост, а сам механизм для временного аддона. brotab работает тем же каталогом, потому что установлен постоянно |
| 2.28 | Стартовые боксы плиток спрашиваются у `model::startBoxes` и для КАЖДОЙ плитки | пустой снимок — это пустой прошлый воркспейс, а не свежее открытие: без этого окно, пришедшее в пустой воркспейс, вылетало из полноэкранного бокса и уменьшалось до плитки. Проверяет `scan_start_boxes` |
| 2.29 | Резкий снимок стола не база бэкдропа, пока включён блюр | прозрачное окно показывает то, что под ним в кадре: резкий кадр под ним — это вспышка рабочего стола без блюра. База — блюр, а блюр готовится на парковке (`primeBackdrop` → `ensureBlur`). Проверяет `scan_backdrop_base` |
| 2.30 | Глиф «✕» рисуется одним правилом на каждой поверхности | кнопка на плитке и кнопка на карточке полосы — одна и та же кнопка; своя доля в полосе делала `close_glyph_fill` бессмысленной там, а глиф не совпадал со своей кнопкой. Проверяет `scan_close_glyph` |
| 2.31 | Шаг по карусели глидит — и стрелки, и alt-tab | это один жест: alt-tab переписывал цели и не запускал глид-клок, и карточки телепортировались вместо движения. Проверяет `runtime_check.py carousel` |
| 2.32 | Карточка за краем окна карусели имеет бокс | уезжающая и въезжающая карточки едут, а не появляются из ниоткуда; без их боксов шаг читается как прыжок. Проверяет `runtime_check.py carousel` |
| 2.33 | Превью окна рисуется по **своему** боксу: `SRenderData.pos/w/h` — это нарисованный бокс, без `renderModif` и без `pWindow`. Damage Hyprland режет по `getTexBox()`, а он модификатор игнорирует (SurfacePassElement.cpp:31); `calculateUVForSurface` режет текстуру по `box/reported` (ElementRenderer.cpp:98). Через модификатор карточка показывала полосу контента, остальное — плита, и мигала на частичной перерисовке. Правит `render::previewBox()`, проверяет `scan_preview_box` |
| 2.34 | Карточка, перешедшая шов кольца, стартует со своего нового бокса, а не из старого | шаг по ряду двигает карточку максимум на слот; через полэкрана едет только карточка шва. Скольжение через весь ряд — это карточка, летящая поверх карусели. На своём слоте она садится за карточку, которая этот слот освобождает. Правило в `startBoxes(…, seamRunW)`, проверяют `origin` и `runtime_check.py carousel` |

## 3. Архитектура

### 3.1 Владение

```
Overview                     единственный владелец состояния; НЕ юнит-тестируем
├── model::Scene             плитки, выбор, интенты              (инвариант → тест)
├── model::Effects           ghosts, pulses, swapfx              (инвариант → тест)
├── model::Strip             карточки стрипа                      (инвариант → тест)
├── model::Recency           порядок фокуса                       (инвариант → тест)
├── model::DragT<WinRef>     ФСМ перетаскивания                  (инвариант → тест)
├── model::Lifecycle         ФСМ владения экраном                (инвариант → тест)
├── model::ScrollState       позиции скролла стрипа               (инвариант → тест)
├── model::SubjectRef        идентичность субъекта, без владения    (инвариант → тест)
├── model::startBoxes        стартовые боксы плиток               (инвариант → тест)
├── view::State              режимы: run / desktop / flip         (чистые данные)
├── clock::Clocks            tween'ы и прогрессы                  (чистые данные)
├── render::Backdrop         снимок стола и кэш блюра             (GL)
├── pixel::PixelCache        подписи, снапшоты                    (GL)
└── CCursorModule            курсор                               (GL)
```

Не покрыто юнитами, покрыто трейсом: `swapWindows`, `toggleAllWorkspaces`,
`switchToWorkspace`, `syncTiles`. Планировать для них юнит-покрытие — не окупается.
Решения рендера — чистые функции в `render/geometry.hpp` (позиция капсулы, полёт
свопа, бейс бэкдропа, радиусы): они не состояние, у них нет владельца.

### 3.2 Подсистема как тип — процедура

1. Измерить границу записи: кто пишет. Пока писал один файл, изоляция уже существует.
2. Поля приватные; наружу — переходы и запросы.
3. Шаблон на тип-ручку, если внутри есть Hyprland-тип. Это и открывает тест.
4. Один файл пишет — из него же и трейс. Запись, которой не было, невозможна.
5. `describe()` принадлежит типу, не эмиттеру.

### 3.3 Три разных вопроса о состоянии

| Вопрос | Метод | Про парковку |
|---|---|---|
| Овервью видно? | `active()` | **нет** |
| Овервью владеет экраном? | `openedOrParked()` | **да** |
| Идёт входная анимация? | `opening()` | не обязана |

`m_opening` не на оси владения. Спрашивать одним именем: `m_life.openingNow()`.
Девять мест писали `active() && opening()` — это один вопрос, заданный девятью способами.

### 3.4 Порядок `paint()`

```
backdrop → tiles/carousel → ghosts → pulses → strip → strip windows
        → strip buttons → pulses → swapfx → drag → aboveLayers → cursor
```

Сидящее ПОВЕРХ контента рисуется ПОСЛЕ него. Кнопки — после своих поверхностей.
Осознанное исключение: `pushOut()` двигает хром из paint.

## 4. Семантика

| Что | Правило |
|---|---|
| `close()` | `m_timeline.seek(1.0 - m_progress)`; при закрытии `m_progress = 1 - timeline.raw()`. Инверсия направления. Менять вместе |
| Кэш блюра | чистый блюр: без dim, без анимации. `blur_strength` — только радиус фильтра. Ключ = srcId + passes/size/resolution/strength, проверяется **каждый кадр вне dirty-guard** |
| Бэкдроп-композит | не протухает, живёт пока источник не сменится. Неудачная попытка уходит в scratch-Framebuffer. TTL в 3 с был причиной чёрного первого кадра |
| Границы перехода | политика, утверждена пользователем: окна скрыты с первого кадра `open`, восстановлены только после полного `close`. Фейда окна нет. Фейд — только у блюра |
| Tween | длительности читаются на месте каждый кадр. Tween владеет только стартовой точкой |
| `close()` | НЕ сбрасывает режим all-workspaces. `setAllOverride(-1)` живёт только в `deactivate()`. Любой инструмент, дёргающий `allws`, обязан восстанавливать режим |
| Браузерный вид | `tabs`/`both` — про все браузеры, не про текущий стол: вход включает all-workspaces, выход возвращает прежнее значение (`m_allForced`). `syncTiles` в этом виде не сверяет число окон с числом плиток — плитки не окна |
| Подпись карточки | `model::truncateTitle` — предел 50 символов, троеточие внутри предела, резка по границе символа. Одна функция на окно и на вкладку | подсчёт по байтам режет кириллическую букву пополам, а «50 + ...» — это 53 символа. Проверяет `title_text` |

## 5. Исходники композитора

Заголовки в `/usr/include/hyprland` **объявляют** функции, но не содержат тел.
`RASSERT` живёт в `.cpp`.

```bash
./tools/sync_upstream.sh          # клонировать + взять ревизии живой сессии
./tools/sync_upstream.sh --check  # сверить, что дерево соответствует сессии
```

| Что | Где |

## 6. Диагностика падений

```bash
ls -t ~/.cache/hyprland/hyprlandCrashReport*.txt | head -1
coredumpctl info <PID> --no-pager        # стек есть там, где отчёт Hyprland пуст
coredumpctl debug <PID> --debugger-arguments="-batch -ex 'bt 20' -ex 'info sharedlibrary' -ex quit"
tail -100 /run/user/$(id -u)/hypr/$(ls -t /run/user/$(id -u)/hypr | head -1)/hyprland.log
```

| Правило | Причина |
|---|---|
| Имя функции в crash-отчёте может быть выдуманным | после hot-reload символизатор резолвит адрес по symtab старой сборки. Сверять `nm -DC build/hyprview.so` |
| `coredumpctl` — источник истины по стеку | crash-отчёт Hyprland может быть без стека |
| `info sharedlibrary` — проверка, загружен ли плагин | отсутствие `hyprview.so` означает выгрузку к моменту падения |

**Запрещено:** `hyprctl --verify-config` (роняет композитор, подсовывает чужие дампы);
`rm -rf /run/user/$(id -u)/hypr/*` (уносит логи живых сессий).

У каждой гипотезы о падении есть красный цикл. Версия без него — не находка.

## 7. Сборка и тесты

```bash
cmake --build build -j$(nproc)          # цель build/hyprview.so
cmake --build build --target reload     # пересобрать + горячая перезагрузка
cd build && ctest --output-on-failure   # 56 проверок
```

**Судить по дате `build/hyprview.so`, не по выводу сборки.** `cmake --build` печатает
`[100%] Built target` при падении make — код 0, ошибки в stderr. Инкрементальная
сборка прячет warning'и в неизменённых TU.

### 7.1 Тесты: 55, две группы

| Префикс | Что это |
|---|---|
| `scan_*` | **статика.** Читают исходники и сверяют с правилом. Не исполняют логику. `scan_render_config` — граница: в чистых заголовках `render/` `cfg::` не бывает вовсе |
| остальные | исполняют код; `hook_signatures`/`load_seam` — против живого бинарника |

## 8. Трейс и автоматизация

```bash
hyprctl eval 'hl.plugin.hyprview.cmd("...")'      # под Lua-конфигом: hl.plugin.hyprview.cmd
python3 tools/runtime_check.py [--list] [lifecycle|scroll|drag|gl]
python3 tools/anim_matrix.py [--quick] [--scenarios]
```

| Правило | |
|---|---|
| Лог — `/tmp/hyprview.log`, не лог Hyprland | grep лога Hyprland вернёт пустоту, читаемую как «плагин молчит» |
| Лог — единственный канал успеха | `hyprctl eval` не печатает возвращаемое значение. Успех — `CMD\|ok`, провал — `CMD\|err` |
| `hyprctl dispatch`/`eval` под Lua-конфигом не доходят до диспетчеров плагина | только `hl.plugin.*` |
| `debug_trace` сбрасывается при каждом reload | включать заново после `reload`, иначе кейсы дают SKIP |
| Приоритет настроек | `kRows` → `set` → rule из `hyprview.animation` → config-значение. **Rule бьёт config** |
| Грамматика | `key=value` через `|`, без пробелов |

| Семейство | Читает |
|---|---|
| `LIFE\|` `SCROLL\|` | `runtime_check.py` |
| `ANIM\|` | `anim_matrix.py` |
| `DRAG\|` `SWAP\|` | никто автоматически: шов ставит состояние, а не двигает мышь |
| `RING\|` `GL\|` `CURSOR\|` `CURSORMV\|` | `runtime_check.py gl`; остальное — чтение глазами |

Формат, битовая маска `debug_trace`, ротация файла: `docs/REFERENCE.md` §3.

## 10. Рабочий процесс

| # | Требование |
|---|---|
| 10.1 | Один логический шаг = один коммит. Коммит только после зелёной сборки |
| 10.2 | Сообщение `type(scope): summary` на английском, тело объясняет why |
| 10.3 | Комментарий в коде не содержит маркер собственного теста | **вес комментариев ≤8% от кода.** Проверяет `scan_comment_weight`: стена — доля (8%), ратчет — **абсолютное число строк-комментариев (≤940)**. Доля штрафует рефакторинг, который удаляет код: метрика растёт, а комментарий не добавлен. Комментарий держит правило и его следствие; история поиска (замеры, отвергнутые версии, «сначала было так») живёт в git
