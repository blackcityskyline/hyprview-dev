# AGENTS.md — hyprview

Плагин Hyprland, C++23. Справочник: `docs/REFERENCE.md`. Ниже — требования, не объяснения.

## 0. Сначала запись, потом правка

- «Выглядит неправильно» → включить `debug_trace`, воспроизвести, прочитать `LIFE|` `DRAG|` `SCROLL|` `SWAP|` `ANIM|` `RING|` `GL|` `CURSOR|`.
- Гипотеза о причине → запись, которая её подтвердит или опровергнет, до правки.
- Правка «на всякий случай» запрещена.
- Отсутствие записи ≠ отсутствие события.
- «Исправлено» — только с живым доказательством.

## 1. Сборка/Тест/Перезагрузка (строго)

1. Правка.
2. `cmake --build build -j$(nproc)`
3. `cd build && ctest --output-on-failure` — 71 проверка.
4. `cmake --build build --target reload`
5. Живая проверка: `tools/runtime_check.py`, `tools/anim_matrix.py` или руками.

- Судить по дате `build/hyprview.so`, не по выводу сборки: `cmake --build` печатает `[100%] Built target` при падении make.
- Зелёная сборка = error **и** warning.
- `debug_trace` сбрасывается при reload — включать заново.

## 2. Коммиты (строго)

- Коммит после каждого шага, как только сборка и тесты зелёные.
- Несколько задач в одном запросе — по коммиту на задачу, последовательно.
- Коммит атомарный: только изменения этого шага.
- Сообщение `type(scope): summary`, английский, тело объясняет why.
- Разные изменения в один коммит не сваливать.
- Работа в отдельной ветке, слияние в `stable`. Пуш не делается.

## 3. TDD

- Новая нетривиальная логика — сначала падающий check.
- Новый тест обязан **краснеть** при откате своей правки.
- Тест, у которого нечего наблюдать, даёт SKIP, а не PASS.
- Проверка, читающая лог, обязана доказывать, что читала.
- Юнит проверяет функцию; неверный аргумент на стороне вызова ловит `scan_*` или трейс.
- Новый ключ конфига — строка в `config.cpp` **и** строка в `README.md`.
- Полный прогон перед коммитом.

## 4. Безопасность сессии

Краш, use-after-free или RASSERT внутри плагина роняет сессию пользователя.

- Рискованные правки (хуки, порядок проходов, teardown, private GL) — только в nested Hyprland.
- Хуки ставятся по demangled-signature substring: `shouldRenderWindow`, `damageSurface`, `CSeatManager::setPointerFocus/setKeyboardFocus`. После обновления Hyprland: `ctest -R hook_signatures`.
- Hot-reload — только целью `reload`. Ручной `plugin load` рядом с hyprpm-копией даёт два инстанса.
- `-fno-gnu-unique` в `CMakeLists.txt` не удалять.
- Перед `git checkout` проверять файлы вне git: tracked на одной ветке + gitignored на другой.
- Запрещено: `hyprctl --verify-config`, `rm -rf /run/user/$(id -u)/hypr/*`.

## 5. Правила кода

1. Immediate-mode GL только через `gl_util.hpp`: `safeRenderRect`, `drawable()`, `dropShadow`, `strokeRing`/`strokeRingPx`.
2. Chrome в monitor-local логических пикселях; перед GL через `pxb()`/`pxr()`; `.round()` обязателен.
3. Всё, что рисует в приватный FBO: `RPT_EXPORT` + `fbSize=(W,H)` с сохранением и восстановлением окружения.
4. Конфиг только через `cfg*`-хелперы (V2 `value()`).
5. Никаких `const double x = cfg::…` в namespace scope.
6. Заголовки Lua (`<lua.h>`, `<lauxlib.h>`) — внутри `extern "C"` (`src/anim.cpp`, `src/clock/curves.cpp`).
7. Порядок `paint()` не менять без причины (`render/painter.cpp`).
8. Файлы, которые ctest компилирует без `hyprland/`, его include не получают никогда.
9. Карта по окнам держит владельца: значение несёт `PHLWINDOWREF` и роняет запись при `expired()`.
10. Каждый `m_place.clocks.*.begin()` стоит рядом с `trace::animStart` либо в списке исключений с причиной.
11. `hl.config{…}` в пользовательском конфиге — под `pcall`; `hl.plugin.load` тоже.
12. `currentFB` — не источник блюра и не источник полос. Источники только `backdropSource()`/`renderBackdropSource()`.
13. Не деактивировать mid-frame: финальный кадр овервью обязан отрисоваться.
14. Владение вводом ≠ скрытие окон. Пока овервью владеет экраном (`openedOrParked()`), хуки `setPointerFocus`/`setKeyboardFocus` не дают фокусу уйти в окна. Хук на `send*` бесполезен.
15. Геометрия в `render/` принимает сторону/якорь/настройки аргументами и никогда не читает `cfg::`. Чистые заголовки: `geometry.hpp`, `tile_look.hpp`. Решение о капсуле, полёте, свопе и содержимом карточки — тоже аргументами.
16. Конфиг читается по месту использования, каждый кадр. Кэш значения в поле — запрещён.
17. `SubjectRef` — идентичность без владения. `windowOf()` не строит `SP` из `s.id`; владеет источник: `enumerate()` пересобирает список живых. Устаревшая идентичность → `null`, не указатель.
18. `src/model/` не называет `PHLWINDOW`. Воркспейсы правилом не покрыты.
19. Окно браузера сопоставляется окну Хайпрленда по pid процесса браузера, один к одному. Два претендента на pid → не сопоставлено никто. Коллизии считаются с обеих сторон.
20. Источник вкладок не содержит ни одного Hyprland-типа. Группа вкладки — окно браузера, никогда воркспейс. Глаголы без транспорта возвращают `false`.
21. PNG читается через `cairo_image_surface_create_from_png` + `createTexture(cairo_surface_t*)`, не через `loadAsset`. `cairo_surface_status` обязателен.
22. Кэш картинок субъекта: ключ `SubjectRef{id, epoch}`, смена epoch очищает кэш целиком. `null`-текстура не хранится.
23. Ключ конфига, который никто не читает — провал. Проверяется выражение поля (`colors.label`), не имя ключа.
24. Матч «окно браузера → вкладки» строится в `buildTiles()`, из того же перечисления, что и плитки.
25. Расширение не пишет файлы ни на одном движке. Мост обязателен.
26. `w->m_title` ≠ `tab.title`: браузер дописывает имя приложения. Заголовок — не ключ сопоставления.
27. Временный аддон не может использовать native messaging. Постоянная установка требует подписанного XPI.
28. Стартовые боксы плиток спрашиваются у `model::startBoxes` для каждой плитки.
29. Резкий снимок стола не база бэкдропа, пока включён блюр. База — блюр, готовится на парковке (`primeBackdrop` → `ensureBlur`).
30. Глиф «✕» рисуется одним правилом на каждой поверхности.
31. Шаг по карусели глидит: и стрелки, и alt-tab.
32. Карточка за краем окна карусели имеет бокс.
33. Превью окна рисуется по своему боксу: `SRenderData.pos/w/h`, без `renderModif` и `pWindow`. Правит `render::previewBox()`.
34. Карточка, перешедшая шов кольца, стартует со своего нового бокса. Правило в `startBoxes(…, seamRunW)`.
35. Пиля заголовка живёт в `render/caption.hpp`. Карточка, накрывшая пилю целиком, убирает её; задевшая краем — позволяет уйти под себя целой.
36. Выбранная карточка садится по своей группе: у вкладки — окно браузера, у окна — воркспейс. «Некуда лететь» = карточка не выбрана. Правило в `model::goesHome()`.

## 6. Архитектура

```
Overview                     единственный владелец состояния; НЕ юнит-тестируем
├── model::Scene             плитки, выбор, интенты              (инвариант → тест)
├── model::Effects           ghosts, pulses, swapfx              (инвариант → тест)
├── model::Strip             карточки стрипа                      (инвариант → тест)
├── model::Recency           порядок фокуса                       (инвариант → тест)
├── model::DragT<WinRef>     ФСМ перетаскивания                  (инвариант → тест)
├── model::Lifecycle         ФСМ владения экраном                (инвариант → тест)
├── model::ScrollState       позиции скролла стрипа               (инвариант → тест)
├── model::SubjectRef        идентичность субъекта, без владения  (инвариант → тест)
├── model::startBoxes        стартовые боксы плиток               (инвариант → тест)
├── view::State              режимы: run / desktop / flip         (чистые данные)
├── clock::Clocks            tween'ы и прогрессы                  (чистые данные)
├── render::Backdrop         снимок стола и кэш блюра             (GL)
├── pixel::PixelCache        подписи, снапшоты                    (GL)
└── CCursorModule            курсор                               (GL)
```

Покрыто трейсом, не юнитами: `swapWindows`, `toggleAllWorkspaces`, `switchToWorkspace`, `syncTiles`.
Решения рендера — чистые функции в `render/geometry.hpp`.

Три вопроса о состоянии: `active()` — овервью видно; `openedOrParked()` — владеет экраном (включая парковку); `opening()` — идёт входная анимация.

### paint()

```
backdrop → tiles/carousel → ghosts → pulses → strip → strip windows
        → strip buttons → pulses → swapfx → drag → aboveLayers → menu → cursor
```

Сидящее поверх контента рисуется после него; кнопки — после своих поверхностей. Исключение: `pushOut()` двигает хром из paint.

Подсистема как тип: один файл пишет — из него же и трейс; поля приватные; шаблон на тип-ручку, если внутри Hyprland-тип; `describe()` принадлежит типу.

## 7. Диагностика падений

```bash
ls -t ~/.cache/hyprland/hyprlandCrashReport*.txt | head -1
coredumpctl info <PID> --no-pager
coredumpctl debug <PID> --debugger-arguments="-batch -ex 'bt 20' -ex 'info sharedlibrary' -ex quit"
tail -100 /run/user/$(id -u)/hypr/$(ls -t /run/user/$(id -u)/hypr | head -1)/hyprland.log
```

- `coredumpctl` — источник истины по стеку; crash-отчёт Hyprland может быть без стека.
- Имя функции в crash-отчёте может быть выдуманным после hot-reload. Сверять `nm -DC build/hyprview.so`.
- `info sharedlibrary` без `hyprview.so` = плагин выгружен к моменту падения.
- У каждой гипотезы о падении есть красный цикл. Версия без него — не находка.

## 8. Трейс и автоматизация

```bash
hyprctl eval 'hl.plugin.hyprview.cmd("...")'      # под Lua-конфигом
python3 tools/runtime_check.py [--list] [lifecycle|scroll|drag|gl]
python3 tools/anim_matrix.py [--quick] [--scenarios]
```

- Лог — `/tmp/hyprview.log`, не лог Hyprland.
- Лог — единственный канал успеха: успех `CMD|ok`, провал `CMD|err`.
- `hyprctl dispatch` под Lua-конфигом до диспетчеров плагина не доходит.
- Приоритет настроек: `kRows` → `set` → rule из `hyprview.animation` → config-значение. Rule бьёт config.
- Грамматика: `key=value` через `|`, без пробелов.
- `debug_trace` сбрасывается при каждом reload.

| Семейство | Читает |
|---|---|
| `LIFE\|` `SCROLL\|` | `runtime_check.py` |
| `ANIM\|` | `anim_matrix.py` |
| `DRAG\|` `SWAP\|` | никто автоматически |
| `RING\|` `GL\|` `CURSOR\|` `CURSORMV\|` | `runtime_check.py gl`; остальное — глазами |
