# Ручные тест-кейсы

Пройти после изменения. Каждый кейс самостоятелен, порядок не важен — можно брать
подмножество по номерам.

**Признак `·часто·`** — гонять после **любого** изменения. Двенадцать штук, 4–6 минут.
Остальные — перед релизом или перед нетривиальным рефакторингом.

```
TC-01  TC-03  TC-10  TC-21  TC-40  TC-46
TC-50  TC-60  TC-62  TC-63  TC-64  TC-70
```

Отобраны не по кругу, а по тому, что ломалось. `TC-62` и `TC-63` — два настоящих
бага пути записи конфига, найденных за один день: `Color::get` не читал
`cfg::override`, и `_style` не принимался для строк со стилем. `TC-40` — «регрессия»,
которой не было. `TC-50` — единственный кейс, где провал стоит сессии, поэтому он
быстрый: дешёвый тест дорогого сбоя.

**Обозначения.** `cmd(X)` — это `hyprctl eval 'hl.plugin.gloview.cmd("X")'`.
Лог — `/tmp/gloview.log`.

**Подготовка (один раз за сессию):**

```bash
cmake --build build -j$(nproc)      # судить по дате build/gloview.so, не по выводу
cmake --build build --target reload # без этого дальше бессмысленно
```

Затем в Lua-конфиге: `hl.config({plugin={gloview={debug_trace=1}}})`
Без этого в логе не будет записей `LIFE|`/`DRAG|`/`SCROLL|`/`ANIM|`/`SWAP|`, и кейсы
на них дадут SKIP, а не результат.

Включить/выключить отдельный кейс, не трогая конфиг: `cmd("set debug_trace 1")`.

## Открытие и закрытие

**TC-01 ·часто· Парковка перед появлением**
Предусловие: ≥2 окна, обычные обои.
`cmd("open")`. В логе ожидается:
```
LIFE|park|own=parked|opening=0|parkTicks=0
LIFE|promote|own=screen|opening=1
```
Визуально: первый видимый кадр **не чёрный**.
Провал: `park` без `promote` — овервью не появилось; `promote` без `park` — первый кадр ушёл без бэкдропа.

**TC-02 ·Видео-обои не вешают парковку**
Предусловие: обои — видео (`animation = fps`).
`cmd("open")`. `LIFE|promote` должен наступить в любом случае.
Провал: овервью застрял невидимым, а он уже владеет экраном — окна без фокуса.

**TC-03 ·часто· Закрытие не оставляет прозрачного кадра**
`cmd("open")`, дождаться показа, `cmd("close")`.
```
LIFE|requestDeactivate|own=screen|opening=0|deactivating=1
LIFE|deactivate|own=screen|opening=0
```
Визуально: между уходом карточек и возвратом стола нет кадра с резкими окнами.
Провал: `deactivate` без `requestDeactivate` — снят в тот же кадр.

**TC-04 ·Закрытие до первого видимого кадра**
Открыть и **сразу** закрыть, не дав показаться.
Ожидается `LIFE|park`, затем `LIFE|abort`, и **без** `LIFE|promote`.
Провал: овервью мигнул.

**TC-05 ·Повторное открытие**
`cmd("open")` → `cmd("close")` → `cmd("open")`. Второе открытие паркуется заново.
Провал: второй раз без `LIFE|park` — состояние не сбросилось.

## Сетка и воркспейсы

**TC-10 ·часто· Переключение воркспейса**
Два воркспейса с окнами. Переключиться стрелкой/digit.
Ожидается `ANIM|begin|op=open` с `from` != `to`.
Провал: карточки сменились мгновенно.

**TC-11 ·Переключение цифрой (digit-jump)**
`cmd("open")`, нажать цифру другого воркспейса.
Ожидается слайд, затем нормальное открытие. В логе — `ANIM|begin` со `style=slidevert` либо `slide`.
Провал: воркспейс переключился, овервью не показало новый.

**TC-12 ·Переключение при пустом воркспейсе**
Переключиться на воркспейс без окон.
Ожидается пустая сетка и стрип, без артефактов.
Провал: пустые карточки или протухший бэкдроп.

**TC-13 ·Переключение во время открытия**
`cmd("open")` и **сразу** переключить воркспейс.
Ожидается: карточки приходят уже для нового, без «прыжка» назад.
Провал: видно возврат к предыдущему содержимому.

## Стрип

**TC-20 ·Появление и уход полосы**
`cmd("open")` / `cmd("close")`. Полоса выезжает и уезжает.
Ожидается `ANIM|op=open|style=...` c ненулевым расстоянием.
Провал: полоса появляется без движения.

**TC-21 ·часто· Скролл полосы**
Достаточно карточек, чтобы `scrollable=1`. Колесо по полосе.
Ожидается `SCROLL|glide|...`; `from`/`target`/`current` в `[0, max]`.
Провал: полоса уехала за крайнее положение, карточки пропали.

**TC-22 ·Сужение полосы во время скролла**
Прокрутить полосу в конец, **не отпуская колесо**, переключить воркспейс.
Ожидается `SCROLL|setMax`, и во всех `SCROLL|` строках `0 ≤ current ≤ max`.
Провал: `current > max` — именно тот баг, который закрывает `ScrollState`.

**TC-23 ·Клик по карточке стрипа**
Клик по карточке воркспейса.
Ожидается переключение на этот воркспейс.
Провал: клик прошёл в окно под овервью.

**TC-24 ·Перетаскивание окна внутри полосы**
Перетащить окно из одной карточки стрипа в другую.
Ожидается обмен местами с анимацией.
Провал: окно пропало или встало в обоих сразу.

**TC-25 ·Двойной клик по окну стрипа**
Один клик, дождаться, затем быстро два клика.
Ожидается: одиночный отменяется, двойной закрывает.
Провал: таймер сработал на чужую карточку или не сработал вовсе.

## Карусель

**TC-30 ·Открытие в карусель**
`cmd("carousel 1")`, `cmd("open")`.
Ожидается ряд карточек, текущая по центру, глубина видна тональным градиентом.
Провал: карточки наложены или без разницы глубины.

**TC-31 ·Прокрутка карусели**
Колесо/стрелки в карусели.
Ожидается `ANIM|begin|op=carousel_step`, центральная карточка меняется, `depth` едет с карточкой.
Провал: сдвиг без смены центра, или периферия нарисована поверх центра.

**TC-32 ·Карусель + закрытие**
Закрыть овервью из карусели.
Провал: остались «призраки» уходящих карточек.

**TC-33 ·Счётчик отростком под тайтлом**
`cmd("carousel 1")`, `cmd("open")` в all-workspaces на 3+ окнах.
Ожидается `n / total` НИЖЕ пилюля с тайтлом, как стебель: плоский верх,
слитый с низом пилюля, скруглённый низ, общий цвет. Не второй овал рядом.
Провал: две отдельные капсулы, зазор между ними, шов потемнее на стыке,
трапеция вместо скругления.

**TC-34 ·Счётчик не ломает отдачу соседних тайлов**
Сетка (`cmd("carousel 0")`), 3+ окна, подвести курсор к крайнему тайлу.
Провал: пилюль тайла уехала вбок сама, без предпросмотра рядом. Регресс:
union-бокс считался вместе с пустым отростком и уезжал в x=0.

## Перетаскивание и своп

**TC-40 ·часто· Своп на гриде**
Перетащить карточку на другую. Ожидается: обе карточки меняются местами **с анимацией**.
В логе: `SWAP|decide|...|slots=1` либо `rA=0 rB=0` (идёт глид), и `ANIM|op=swap|surface=grid` с `from` != `to`.
Провал: `slots=0` при `rA=1 rB=1`, или `from == to` при слотах 1.
Подробнее — [TC-47](#tc-47-почему-своп-иногда-не-анимируется).

**TC-41 ·Своп ПКМ на гриде**
То же правой кнопкой.
Провал: ведёт себя как ЛКМ или ничего.

**TC-42 ·Снос окна в kill-зону**
Перетащить карточку в зону сноса (левый край).
Ожидается `DRAG|branch|name=Tile->killZone`, окно закрывается.
Провал: карточка вернулась на место.

**TC-43 ·Снос по двойному клику**
Двойной клик по карточке воркспейса.
Ожидается `DRAG|branch|name=Tile->carouselFocus|idx=...`, затем закрытие по `exit_on_click`.
Провал: только фокус.

**TC-44 ·Перетаскивание без смещения = клик**
Нажать и отпустить без движения (порог 8px).
Ожидается клик по окну, а не драг.
Провал: карточка «прыгнула» и вернулась.

**TC-45 ·Авто-коммит alt-tab**
Включить `alt_tab_commit_on_release`, сделать alt-tab и отпустить.
Провал: переключилось не на то окно.

**TC-46 ·часто· Одно отпускание — одна ветка**
Любой драг. В логе на каждое отпускание: **ровно одна** `DRAG|release|...` и **хотя бы одна** `DRAG|branch|name=...`.
Провал: `release` без `branch` — отпускание ничего не решило; две ветки на одно — потерянная пара.

<a id="tc-47-почему-своп-иногда-не-анимируется"></a>
**TC-47 ·Почему своп иногда не анимируется**
Если на TC-40 нет анимации, **сначала проверь режим**:
`cmd("state")` → `show_all_workspaces` должен быть 0. В режиме всех воркспейсов
у сеточных карточек обнулён `target`, `currentBox()` держит их на `natural`,
`tileAtRest` ложно и слот-обмен пропускается — грид покажет только пульс, и это
**не регрессия**. Лечится `cmd("allws 0")`.

## Фокус и ввод

**TC-50 ·часто· Овервью владеет фокусом**
Открыть овервью, кликнуть по карточке.
Провал: клик ушёл в окно под овервью — значит `shouldRenderWindow` или
`setPointerFocus`/`setKeyboardFocus` не встали, `initialize()` вернул false.
**Сразу** `ctest -R hook_signatures`.

**TC-51 ·Клавиши не уходят в окна под овервью**
Открыть, нажать букву/цифру.
Провал: сработал бинд окна под овервью.

**TC-52 ·Фокус на паркованных кадрах**
Открыть и **не дожидаясь появления** нажать клавишу passthrough.
Ожидается: сработало окно, сфокусированное **до** открытия.
Провал: см. `m_focusOutside` в `overview.hpp` — поле мёртвое, гарантии нет.

**TC-53 ·Возврат фокуса после закрытия**
Закрыть овервью, сразу нажать клавишу окна.
Ожидается: фокус вернулся рабочему столу без ожидания движения мыши.
Провал: нужен клик мышью, чтобы фокус вернулся.

## Конфиг: путь записи

**TC-60 ·часто· `set` на числовой ключ**
`cmd("set strip_height 180")` → `CMD|ok`, полоса стала выше. `cmd("set strip_height 0")` — вернуть.
Провал: `unknown key` или значение не применилось.

**TC-61 ·`set` на строковый ключ**
Ключи плоские, без секции: `cmd("set layout columns")` → `CMD|ok`, раскладка сменилась.
Провал: как выше.
> Не `set grid layout ...`. Поле называется `grid.layout`, но регистрируется как
> `plugin:gloview:layout` (config.cpp:196) — `setTuning` ищет по плоскому имени.

**TC-62 ·часто· `set` на цветовой ключ**
`cmd("set backdrop_color 73070a10")` → `CMD|ok`, цвет применился.
Провал: `ok`, но ничего не изменилось — `Color::get` не читает override.

**TC-63 ·часто· `set` на ключ анимации**
`cmd("set ws_enter_style pop")` → `CMD|ok`, вход плиток стал pop.
Провал: `unknown key` — `_style` снова не принимается.

**TC-64 ·часто· `set` на неизвестный ключ**
`cmd("set nosuchkey 1")` → должно быть `set: unknown key nosuchkey`.
Провал: приняло.

**TC-65 ·`set` на неизвестный суффикс**
`cmd("set ws_enter_bogus 1")` → `unknown key`.
Провал: приняло.

**TC-66 ·Снятие значения пустой строкой**
`cmd("set strip_height ")` → `CMD|ok`, значение вернулось к дефолту из конфига.
Провал: осталось перекрытое.

## Формат трейсов

**TC-70 ·часто· Грамматика**
Взять все `LIFE|`, `DRAG|`, `SCROLL|`, `SWAP|`, `ANIM|` из лога.
Каждый сегмент после первых двух — `key=value`, без пробелов и без `|`.
Провал: поле добавлено прозой, харнесс его не разберёт.

**TC-71 ·`LIFE` идёт полным циклом**
Один open/close. Четыре записи: `park` → `promote` → `requestDeactivate` → `deactivate`.
Провал: пропущена любая из четырёх.

**TC-72 ·`SWAP|decide` всегда пишется**
Любой своп на гриде → есть `SWAP|decide|ia=..|ib=..|restA=..|restB=..|slots=..`.
Провал: запись не дошла — решение принимается мимо трейса.

**TC-73 ·Пустой лог — это не успех**
`cmd("set debug_trace 0")`, сделать действие, `cmd("set debug_trace 1")`.
Записей нет. Убедиться, что дело в выключенном трейсе, а не в сломанной эмиссии —
включить обратно и повторить.
Провал: трейс включён, а записей нет.

## Сторожевые

**TC-80 ·Субпиксельные боксы**
Монитор с дробным масштабом (1.25/1.5), карусель. Быстро переключать соседние
карточки, пока бокс анимируется.
Провал: пропущенный кадр, «дырки» в рамках. Это единственный кейс, где провал
**невосстановим** — `RASSERT` в композиторе роняет сессию.

**TC-81 ·Быстрые открытия подряд**
10 раз `cmd("open")` / `cmd("close")` без пауз.
Провал: краш, зависание, или в логе `LIFE` без парных `park`/`promote`.

**TC-82 ·Смена числа окон во время открытия**
Открыть овервью, не закрывая, запустить окно из терминала.
Провал: краш, или карточки в невалидных боксах.

## Если кейс упал

1. `ls -t ~/.cache/hyprland/hyprlandCrashReport*.txt | head -1` — **до** догадок.
2. Имя функции в отчёте может быть выдуманным: после hot-reload символизатор резолвит
   адрес по старой сборке. Сверять `nm -DC build/gloview.so`.
3. `tail -100 /run/user/$(id -u)/hypr/$(ls -t /run/user/$(id -u)/hypr | head -1)/hyprland.log`
4. **Не** запускать `hyprctl --verify-config` — роняет композитор и подсовывает чужие дампы.
5. Не делать `rm -rf /run/user/$(id -u)/hypr/*` — уносит логи живых сессий.

## Что автоматизировано

`python3 tools/runtime_check.py [--list] [lifecycle|scroll|drag]` покрывает часть
TC-01…TC-03 и TC-21/TC-22 по трейсу. Остальное — визуальное, только руками.
Автоматизированное считать зелёным можно только вместе с ручным: у харнесса есть
случай, когда он проходит на записях, не проверяющих ничего (см. комментарий
`meaningful` в `tools/runtime_check.py`).
